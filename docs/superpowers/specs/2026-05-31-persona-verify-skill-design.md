# Persona 验证 Skill — 产品设计文档

## 一、背景与目标

### 问题
开发淘宝店铺诊断工具时，开发者不熟悉淘宝运营，无法判断：
- 页面对真实卖家是否好用（UX 问题）
- 诊断逻辑是否正确、建议是否有用（业务有效性）
- 按工具建议操作，能否真正提升销量（商业价值）

### 目标
一个通用 skill，输入身份描述和测试数据，自动以该身份视角验证网页，生成结构化报告并可选执行修复。

## 二、核心设计

### 2.1 一次配置，重复使用

用户在项目根目录的 `persona-verify.yaml` 中填写：

```yaml
# 身份描述（必填）
identity: |
  开了3个月淘宝店，卖古装演出服，月销5单。
  不懂运营推广，标题是复制同行的，没做过竞品分析。

# 目标页面（必填，相对于项目根目录）
target: index.html

# 测试操作（必填）
operations:
  - tab: 竞品分析
    action: 在输入框粘贴竞品JSON数据，点击"分析数据"
  - tab: 标题诊断
    action: 输入"古装演出服女成人舞台定制"，点击"诊断"
  - tab: 推广分析
    action: 勾选已开通渠道，点击"生成推荐"

# 浏览器（可选，默认自动检测）
browser: edge
```

每次调用 skill 自动读取，无需重复输入。

### 2.2 工作流

```
用户调用 /persona-verify
    │
    ├─ 1. 读取 persona-verify.yaml 配置
    │
    ├─ 2. 浏览器打开 target 页面，截图各 Tab 初始状态
    │
    ├─ 3. 按 operations 逐条真实操作
    │     填数据 → 点击 → 截图结果 → 记录交互行为
    │
    ├─ 4. 启动子代理（注入 identity 人格）
    │     子代理看截图 + 操作结果，以卖家视角回答：
    │       · 哪里卡住了？什么看不懂？
    │       · 工具给的建议对卖家有用吗？
    │       · 按建议做，能提升销量吗？
    │
    ├─ 5. 生成结构化报告
    │     ├─ UX 痛点（按严重程度排序）
    │     ├─ 诊断有效性评估（逐功能判断）
    │     ├─ 销量影响判断（综合评估）
    │     └─ 修复方案（代码改动，按 P0/P1/P2 优先级）
    │
    └─ 6. 用户确认后，执行代码修复
```

### 2.3 关键技术点

**隔离性**：子代理不携带开发上下文，不知道页面代码怎么写，只知道"面前有个网页，我要用它完成某个任务"。

**真实操作**：通过浏览器实际打开页面、点击按钮、输入内容，不是读源码模拟。

**身份驱动**：用户的 identity 描述被转化为子代理的人格设定，影响子代理的判断标准和关注点。

## 三、报告结构

```markdown
## Persona 验证报告
**身份：** [用户的 identity 摘要]
**时间：** [验证时间]

### 一、UX 痛点（按严重程度排序）
1. [痛点标题] — 卡在哪个步骤，为什么困惑
2. ...

### 二、诊断有效性评估
| 功能 | 建议是否有效 | 问题 |
|------|------------|------|
| 标题诊断 | 有效/部分有效/无效 | 具体问题 |
| 竞品分析 | ... | ... |
| 推广分析 | ... | ... |

### 三、销量影响判断
按工具建议执行后，预计 30 天内的销量变化及理由。

### 四、修复方案
- [P0] 阻塞性问题
- [P1] 重要但不阻塞
- [P2] 锦上添花
```

## 四、技术实现

### 4.1 Skill 文件结构

```
.claude/skills/persona-verify/
  skill.md          # Skill 主文件（系统提示词 + 工作流指令）
  config-template.yaml  # 配置模板（用户复制为 persona-verify.yaml）
```

### 4.2 依赖

- 浏览器可用（Edge/Chrome）
- 用户项目目录下存在 `persona-verify.yaml`
- 子代理能力（Agent tool）

### 4.3 与现有工具的关系

| 现有能力 | 使用方式 |
|----------|----------|
| Agent tool | 启动子代理进行身份模拟 |
| frontend-design skill | 修复 UI 问题时参考 |
| Bash (start 命令) | 打开浏览器 |

---

## 五、不做

- 不写自动化测试脚本（用户不会维护）
- 不连接外部测试平台
- 不做多身份批量测试（需求明确后再考虑）
- 不修改被测页面之外的代码
- 不自动 commit（用户确认后再提交）

---

## 六、验收标准

| 验收项 | 要求 |
|--------|------|
| 配置读取 | skill 启动后正确读取 persona-verify.yaml，报错明确 |
| 浏览器启动 | 能打开 target 页面，截图各 Tab |
| 测试操作 | 按 operations 逐条执行真实输入和点击 |
| 身份模拟 | 子代理输出的困惑和建议与该身份特征一致 |
| 报告完整 | 包含 UX 痛点、诊断有效性、销量判断、修复方案四部分 |
| 修复执行 | 用户确认后按优先级改代码 |
| 通用性 | 换一个项目，换一个 identity，skill 同样可用 |
