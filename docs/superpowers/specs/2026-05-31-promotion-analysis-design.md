# 推广活动分析 — 产品设计文档

## 一、背景与目标

### 问题
平台推广活动太多（直通车、引力魔方、万相台、淘客、聚划算、天天特卖、运费险、淘金币……），卖家难以判断：
- 哪些渠道值得继续投？
- 哪些应该暂停或砍预算？
- 同行在用什么，我缺了什么？

### 目标
一个**数据驱动的推广 ROI 分析工具**，基于千牛后台的真实花费数据 + 淘宝搜索结果中的同行活动标签，给出可执行的推广优化建议。

---

## 二、数据来源

| 数据类型 | 来源 | 获取方式 |
|----------|------|----------|
| 用户推广花费 & 产出 | 千牛卖家后台 | 用户手动录入 |
| 用户已开通的服务工具 | 千牛卖家后台 | 用户手动勾选 |
| 同行服务工具标签（运费险/淘金币/7天无理由/极速退款等） | 淘宝搜索结果页 | 浏览器扩展自动抓取 |
| 同行活动标签 | 淘宝搜索结果页 | 浏览器扩展自动抓取 |

---

## 三、数据模型

### 3.1 推广渠道（用户录入，localStorage）

```json
{
  "id": "uuid",
  "name": "直通车",
  "type": "paid",        // paid | platform | tool
  "spend30d": 1500,      // 近30天花费（元）
  "revenue30d": 4500,    // 近30天成交额（元）
  "status": "active",    // active | paused | considering
  "budgetShare": 0,      // 自动计算：该渠道花费 / 总花费
  "roi": 0,              // 自动计算：revenue30d / spend30d
  "notes": ""
}
```

### 3.2 我的服务工具（用户勾选，localStorage）

```json
{
  "freightInsurance": false,   // 运费险
  "goldCoins": false,          // 淘金币
  "sevenDayReturn": false,     // 7天无理由
  "fastRefund": false,         // 极速退款
  "globalDistribution": false  // 全球分销
}
```

### 3.3 同行对标数据（竞品搜索结果中提取）

复用竞品分析的 `processData()` 产物：
- 同行服务工具覆盖率（运费险 X%、淘金币 Y%……）
- 同行活动标签频率
- 同行均价、价格分布

## 四、分析逻辑

### 4.1 自身 ROI 诊断

| 档位 | ROI | 含义 | 标签色 |
|------|-----|------|--------|
| 健康 | ≥ 2.0 | 每花1元赚回2元以上 | 绿 |
| 关注 | 1.0 ≤ ROI < 2.0 | 微利或持平，需优化 | 黄 |
| 危险 | < 1.0 | 亏本 | 红 |

附加规则：
- 花费集中度 > 60%（单一渠道占总预算 60%+）→ 提示"过度依赖单一渠道"风险
- 总 ROI < 1.0（整体亏本）→ 综合评分直接标红

### 4.2 同行对标

从竞品搜索结果中：
1. 统计各服务工具标签的同行覆盖率（运费险覆盖率 = 有运费险标签的商品数 / 总商品数 × 100%）
2. 统计平台活动标签（聚划算、天天特卖等）的同行覆盖率
3. 同用户已开通的工具/活动做比对，标记"缺失"项

### 4.3 综合评分

```
总评分 = ROI维度(50%) + 渠道多样性(25%) + 同行对标(25%)
```

- **ROI维度**（50分）：总ROI ≥2→满分，1-2→30分，<1→10分
- **渠道多样性**（25分）：3条以上→满分，1-2条→15分，0条→0分
- **同行对标**（25分）：缺失工具 ≤1→满分，2-3→15分，4+→5分

### 4.4 行动清单排序

```
优先级1：危险ROI的渠道 → 建议暂停/砍预算
优先级2：健康ROI的渠道 → 建议追加预算
优先级3：同行覆盖率高但你未开通的工具/活动 → 建议开通
优先级4：关注ROI的渠道 → 建议优化后观察
```

## 五、页面布局（推广分析 Tab）

### 5.1 整体结构

左右两栏布局（同竞品分析页）：

**左侧面板（380px）**：
- 推广渠道录入区（表格 + 添加按钮）
- 我的服务工具勾选区（checkbox 列表）
- 数据来源选择（复用当前竞品搜索数据 / 手动输入同行数据）
- "开始分析" 按钮

**右侧面板**：
1. ROI 诊断总览卡片（环形图 + 三维度进度条）
2. 渠道健康度列表（绿/黄/红标记，每个渠道一行，含 ROI、花费占比、建议）
3. 同行对标卡片（服务工具覆盖率对比表）
4. 行动清单（优先级排序，3-5条）
5. 原始数据表（可折叠）

### 5.2 渠道录入 UI

- 表格形式，每行：渠道名、类型下拉（付费推广/平台活动/服务工具）、近30天花费、近30天成交额、状态
- 底部"添加渠道"按钮
- 预设模板按钮（一键填入：直通车、引力魔方、万相台、淘客）
- 每条可编辑、可删除
- 自动计算 ROI 和花费占比的预览

### 5.3 样式规范

沿用现有 CSS 变量：`--brand: #ff5000`，卡片白底圆角 10px，`box-shadow: 0 2px 8px rgba(0,0,0,.06)`

## 六、与现有功能的关系

| 现有功能 | 关系 |
|----------|------|
| 竞品分析 Tab | 推广分析复用其搜索结果中的同行活动标签 + 服务工具数据。用户需先在竞品分析 Tab 完成一次搜索，再切到推广分析 Tab 分析 |
| 明日清单 Tab | 推广分析的"行动清单"结果可生成待办任务写入明日清单 |
| 浏览器扩展 | 不需要改动，活动标签抓取已就绪 |

| 键名 | 内容 |

| `tb_promo_channels` | 推广渠道数组 |
| `tb_promo_my_tools` | 已开通服务工具对象 |

## 八、不做

- 不自动连接千牛API拉取数据（千牛无公开API，纯前端做不到）
- 不做推广数据的自动同步
- 不做直通车关键词级分析（太细，先做渠道级）
- 不修改浏览器扩展

---

## 九、验收标准

| 验收项 | 要求 |
|--------|------|
| 渠道录入 | 可添加、编辑、删除推广渠道，数据存入 localStorage，刷新后保持 |
| ROI 计算 | 录入花费和成交额后自动计算 ROI，正确分档标记颜色 |
| 综合评分 | 环形图展示，三维度进度条正确 |
| 同行对标 | 复用竞品搜索结果，正确计算各工具覆盖率并与用户已开通工具比对 |
| 行动清单 | 按优先级输出 3-5 条具体建议 |
| 服务工具勾选 | 勾选状态持久化 |
| 样式一致性 | 与现有页面风格统一，无样式冲突 |
| 无控制台报错 | 所有交互路径无 JS 异常 |
