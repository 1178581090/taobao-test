# 推广筛选增强 — 设计文档

**日期：** 2026-06-01
**状态：** 设计确认中

---

## 1. 问题与目标

### 当前问题

1. 千牛推广和营销子页面过多（17 个），内容眼花缭乱
2. 千牛已有智能推荐（推广中心商品成交锦囊）和一键操作，但工具还在教手动步骤，定位冲突
3. 千牛的自动托管会乱报名活动，扣费项叠加，用户不知道钱花在哪
4. 工具缺少费用预估和收入预期，用户无法判断付费推广是否值得
5. 探索千牛后发现 3 个完全没覆盖的功能（爆款竞价、推广工具），部分渠道描述不准确

### 目标

- 新增预算面板——勾选活动后实时计算月支出和预期收益
- 扫描千牛推广中心的商品成交锦囊（千牛为每个商品推荐的推广策略），作为收益预估的数据源
- 补全遗漏的千牛功能（爆款竞价、推广工具）
- 修正描述不准的渠道（淘宝联盟、品牌新享、淘宝秒杀）
- 排除营销托管（黑箱操作，用户不需要）

## 3. 数据获取层

### 3.1 扩展现有 scan-qianniu.js

在扫描脚本中新增一个抓取目标：推广中心首页。

**URL:** `https://myseller.taobao.com/home.htm/tuiguangcenter_new/`

**提取内容：**

```
商品成交锦囊区域：
  商品A（名称 + ID）→ 推荐策略 → 策略类型 → 价格信息
  商品B → ...
  商品C → ...
```

**输出新增字段 `productRecommendations`：**

```json
{
  "productRecommendations": [
    {
      "productName": "原版贾宝玉妙玉林黛玉古装舞台剧演出服",
      "productId": "984528704511",
      "strategy": "精准关键词锁屏",
      "channelHint": "关键词推广",
      "channelId": "keywordPromo",
      "priceInfo": "1元抵101元",
      "rationale": "服饰箱包定制匹配高转化搜索词"
    }
  ]
}
```

**`channelHint` 到 `channelId` 的映射表（维护在扫描脚本中）：**

| channelHint（千牛文本） | channelId（工具内部） |
|------------------------|---------------------|
| 关键词推广 | keywordPromo |
| 人群推广 / 精准人群推广 | crowdPromo |
| 内容推广 | contentPromo |
| 货品全站推 | allStorePromo |
| 淘宝联盟 | tbUnion |

映射表放在扫描脚本中，不在工具前端，千牛改版时更新映射即可。

### 3.2 错误处理

- **DOM 变化导致提取失败** → 该页面返回空数组，不影响其他页面数据。下次扫描自动重试
- **网络超时（30 秒）** → 跳过当前页面，剩余页面继续
- **登录态过期** → 提示用户重新运行 `fetch-page.js` 登录
- **连续 3 次扫描失败** → 保留上次成功数据，前端显示"数据获取失败，使用 X 天前的旧数据"
```

## 4. 预算计算器

### 4.1 位置

活动筛选 Tab 左侧面板，店铺状态卡片下方。

### 4.2 数据格式统一

**`monthlyCost` 必须区分可计算和不可计算：**

所有 ACTIVITY_RULES 中的 `monthlyCost` 遵循统一格式：

| 格式 | 示例 | 可计算 |
|------|------|--------|
| `num` | `900`（纯数字，单位：元/月） | ✅ |
| `null` | 免费活动 | — |
| `"按成交抽佣 5%~10%"` | 文字描述 | ❌ 跳过，不参与加总 |

预算计算时只累加 `typeof monthlyCost === 'number'` 的项，文字描述的单独列出不计入总和。

### 4.3 千牛推荐价格处理

千牛扫描到的 `priceInfo` 不做自动解析，**只在卡片上作为参考文本展示**，不参与预算计算。例如 "1元抵101元" 在卡片显示为 "千牛试投价：1元抵101元"。

### 4.4 UI 结构

```
┌─────────────────────────┐
│ 💰 预算计算器            │
│                         │
│ 月预算: [____1500___] 元 │
│   （保存在 localStorage  │
│    键名 tb_af_budget）   │
│                         │
│ 付费活动（勾选预估花费）: │
│ ☑ 关键词推广  900/月    │
│ ☑ 人群推广    1500/月   │
│ ☐ 货品全站推  1500/月   │
│ ☐ 淘宝联盟    按成交抽佣 │
│                         │
│ ─────────────────────── │
│ 可计算月支出: ¥2,400    │
│ （不含按成交抽佣项目）    │
│ ⚠ 超出预设预算 ¥900     │
│                         │
│ 预计月曝光: 28,000-56,000│
│ 预计月点击: 280-1,120   │
│ （基于类目均价估算）     │
└─────────────────────────┘
```

**空状态（无付费活动或全为免费）：**

```
┌─────────────────────────┐
│ 💰 预算计算器            │
│                         │
│ 🎉 所选活动全部免费      │
│ 无需预算规划             │
└─────────────────────────┘
```

**预算输入校验：**
- 空或非数字 → 默认 1500
- ≤ 0 → 不显示超支警告，视为"无预算上限"

### 4.5 计算逻辑

- **费用** = 累加所有 `typeof monthlyCost === 'number'` 的已勾选活动
- **CPC 均价** = 从 ACTIVITY_RULES 的 `cpcRange` 字段读取（新增字段），不同类目可设不同区间。演出服默认 `{min: 0.5, max: 2}`
- **曝光** = Σ(日预算 ÷ cpcRange.max ~ 日预算 ÷ cpcRange.min) × 30
- **点击** = 曝光 × 预估点击率（1-2%，取区间）
- **超支检测** = 总月支出 - 用户设定预算 > 0 时标红
- **预算持久化** = localStorage 键名 `tb_af_budget`，刷新后恢复

### 4.6 与活动卡片收益预估的关系

预算面板和活动卡片各司其职：
- **预算面板**：宏观——"全选了要花多少钱，总曝光多少"
- **活动卡片 `expectedReturn`**：微观——"单开这一个大概能带来什么"

两者不互相引用，卡片上的 `expectedReturn` 是静态文本，预算面板是动态计算。如果同一项活动的数字有出入，以预算面板的计算为准（因为它是基于用户实际日预算设置的）。

### 4.7 数据时效

扫描数据超过 7 天时，预算面板顶部显示："⚠ 数据已过期（上次扫描：2026-05-25），建议重新扫描获取最新商品推荐"。检测逻辑：`scannedAt` 与当前日期比较。
